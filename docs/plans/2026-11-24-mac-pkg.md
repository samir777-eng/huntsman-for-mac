# 0.5.0: Mac installer (.pkg wizard, self-contained app)

## Baseline (2026-11-24)
- master = v0.4.2. Mac install is `install.sh` from source: needs Homebrew Python 3.11–3.13 (+ Homebrew libusb), builds
  a venv into `~/Applications/Huntsman for Mac.app`, a nested `Huntsman Lighting.app` (shell launcher → venv python
  `service.py`), per-user LaunchAgent `io.github.huntsman-for-mac.lighting`, ad-hoc codesign.
- Input Monitoring is attributed to the Python binaries, not the app (TCC.db, 2026-11-24).
- Windows already ships a PyInstaller one-folder build (packaging/windows/huntsman.spec, `--version`/`--self-test`).

## Problem
Non-developers can't install on the Mac without Terminal, Homebrew and Python. The owner wants a normal installer:
double-click .pkg → Intro → License (GPL) → Install → Done. Unsigned at first.

## Spike (2026-11-24, scratchpad prototype; evidence in the session report)
- PyInstaller freezes app.py (pywebview Cocoa/WKWebView, pyobjc), service.py (menu bar), pyusb with libusb from the
  `libusb-package` wheel (arm64, macOS ≥ 11; Homebrew's dylib needs macOS 26), ctypes IOKit/CF. `--version` and
  `--self-test` pass frozen; a frozen probe opened a WKWebView window + menu bar item. 16 s build.
- universal2 fails (cffi/numpy/libusb are arm64-only) → arm64 only. Minimum macOS 14.0 (numpy wheel).
- The service needs its own frozen executable inside the nested `Huntsman Lighting.app` (own bundle id → own TCC/menu
  name); `--service` on the main executable would be attributed to the main app.
- Nested app as a full copy (70 MB app / 31.6 MB pkg; all codesign checks pass). Symlinked Frameworks breaks strict
  verification of the nested app.
- pkgbuild + productbuild + distribution.xml (welcome, license, conclusion), `/Applications`, `BundleIsRelocatable =
  false` for both bundles (else Installer "upgrades" the ~/Applications copy in place).
- Ad-hoc signature → designated requirement is a cdhash → TCC grants likely reset each update. A self-signed
  certificate gives a stable requirement (identifier + certificate leaf); tested locally.

## Decisions (owner, 2026-11-24)
- Self-signed certificate; private key as a GitHub Actions secret (owner OKs the secret step when it happens).
- Apple Silicon only (Intel keeps install.sh).
- The pkg moves an existing install.sh copy (`~/Applications/Huntsman for Mac.app` of the console user) to the
  Trash; settings in Application Support stay.
- Uninstall: Keyboard tab → "Uninstall…" in the app; uninstall.sh updated for /Applications.
- CI: GitHub-hosted macOS arm64 runner only (public repo, never the fleet). install.sh stays for developers.

## Architecture
- `packaging/mac/huntsman-mac.spec`: two EXEs/BUNDLEs (main `Huntsman for Mac.app`, service `Huntsman Lighting.app`
  nested at `Contents/Library/LoginItems/`, full copy), Info.plists from packaging/ (LSMinimumSystemVersion 14.0,
  CFBundleVersion bumped per release), icon.
- Code:
  - huntsman_core: when frozen, load the bundled libusb first.
  - platforms/bundle.py + self-test: Mac-only module list; native checks (dlopen libusb, IOKit/CF symbol lookup,
    no init, no USB traffic); service executable has its own `--self-test`.
  - service.open_app: `open -b io.github.huntsman-for-mac` when frozen.
  - app.start_service: when frozen and the LaunchAgent is missing or points elsewhere, write it (with
    `AssociatedBundleIdentifiers`) and bootstrap it, as Windows does with its Run key; dev installs unchanged.
  - app log: stdout/stderr to `~/Library/Logs/Huntsman for Mac.log` when frozen.
  - Uninstall: `Api.uninstall` + Keyboard tab button with confirmation: stop service (restores firmware lighting),
    `launchctl bootout` + remove the LaunchAgent, remove `/Applications/Huntsman for Mac.app` (admin prompt via
    `osascript … with administrator privileges`), `pkgutil --forget`, then quit. Settings kept (said in the dialog).
- `packaging/mac/pkg/`: distribution.xml, resources (welcome.html, conclusion.html, LICENSE), scripts:
  - preinstall: stop the running window and service (service stop restores lighting).
  - postinstall: move the console user's `~/Applications/Huntsman for Mac.app` (install.sh copy) to that user's
    Trash; repoint an existing per-user LaunchAgent to /Applications and restart it; nothing for new installs (the
    app does it on first launch).
- `tools/build_mac_pkg.sh`: build both apps, sign (identity from env, ad-hoc fallback), smoke-test, pkg.
- `.github/workflows/mac-build.yml` (macos-15 arm64, GitHub-hosted): build, sign with the secret cert (ad-hoc if the
  secret is absent, e.g. forks), smoke-test, `sudo installer -pkg` on the runner + self-test from /Applications,
  upload artifact; on release publish, attach `Huntsman-for-Mac-<version>.pkg` (tag must equal version).

## Tests first
- Unit (pytest, simulated): libusb path selection when frozen vs not; open_app frozen; start_service writes the
  LaunchAgent only when frozen and missing/stale (temp HOME, fake launchctl); uninstall steps in order with fakes
  (no real launchctl/osascript); log redirection; bundle module list.
- UI (demo mode): Uninstall button + confirmation text; cancel does nothing.
- Packaging: spec/pkg file checks (relocatable false, min OS 14, bundle ids, license present), postinstall/preinstall
  shell tests in a temp HOME with stubbed launchctl (Trash move, LaunchAgent repoint), shellcheck if available.
- CI: frozen `--self-test` of both executables before and after `installer` on the runner.

## Hardware / owner checks (one at a time, on this Mac, after CI builds the pkg)
Open Anyway flow; app opens without a second prompt; install.sh copy moved to Trash; menu bar service from the
frozen build; lighting + actuation + key tester from the frozen app; Input Monitoring/Microphone names; reinstall a
newer build → permissions kept; Uninstall… removes everything and the keyboard types/lights normally.

## Rollback
Releases keep install.sh; a bad pkg is removed from the release; Uninstall… or uninstall.sh cleans up.
